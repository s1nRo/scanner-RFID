# Учёт посещаемости по RFID-картам

Студент прикладывает карту к USB-считывателю IronLogic — время прихода
проставляется в вашем же списке группы.

**Пошаговое руководство — [instruction.md](instruction.md):**
установка драйвера, подготовка списков, привязка карт, отметка, отчёты.
Ниже — устройство проекта и принятые решения.

ФИО, номера групп, коды карт и серийные номера в примерах, тестах и режиме
`mock` вымышлены. Личные таблицы и базы данных исключены из Git.

## Как всё устроено

**`tables/` — корень, в котором лежат папки предметов.** Одна папка — один
предмет, её имя и есть название. Внутри ваши списки, по файлу на группу.
Программа дописывает в эти файлы колонки с датами.

Папок она не создаёт и файлы не переносит — раскладку ведёте вы. Файлы,
лежащие в самой `tables/` мимо папок, ни к какому предмету не относятся
и не используются; `rfid subjects` и `rfid doctor` о них напомнят.

```
tables/
  Бургеростроение 1 курс/          <- предмет
    1000000.10001 список.xlsx      <- группа
    1000000.10002 список.xlsx      <- другая группа
  Матанализ 2 курс/
    ...
```

Список предметов — это просто список подпапок, где нашлись `.xlsx`.
Отдельного справочника нет: создать предмет — значит создать папку
в проводнике. Другой корень задаётся флагом `--tables`.

## Быстрый старт

Нужен Python 3.11 или новее. В распакованной папке один раз:

```powershell
.\install.cmd     # создаёт venv, ставит программу, заводит data\ и tables\
.\rfid.cmd        # меню: спросит, что делать
```

`install.cmd` можно запускать повторно — так ставится новая версия после
распаковки свежего архива поверх старого. `data\` и `tables\` при этом
не трогаются.

`rfid.cmd` запускает программу из любой папки:

| Оболочка | Вызов |
|---|---|
| PowerShell | `.\rfid.cmd doctor` |
| cmd.exe | `rfid.cmd doctor` |
| Git Bash | `./rfid.cmd doctor` |
| откуда угодно | `D:\путь\к\папке\rfid.cmd doctor` |

Ниже для краткости пишется просто `rfid`.

**Рабочая папка.** База (`data\attendance.db`) и списки групп (`tables\`)
всегда лежат рядом с `rfid.cmd`, из какой бы папки его ни запустили.
Другая рабочая папка — флаг `--home` или переменная `RFID_HOME`.
Если рабочую папку не найти, программа откажется работать, а не заведёт
пустую базу в случайном месте: иначе отметки ушли бы мимо журнала.

## Формат списка группы

Программа подстраивается под обычный список, а не требует своего формата:

- **группа** ищется над шапкой тремя способами: «Группа 1000000/10001»,
  затем номер по виду (подходит «ИКНК 1000000/10002» без слова «Группа»),
  затем первая непустая строка; имя файла — последнее средство;
- **шапка** находится по ячейке со словом «ФИО»;
- **студенты** идут подряд ниже, до первой пустой ячейки с ФИО;
- всё, что ниже списка (примечания, «Староста: …»), не трогается;
- номера в первой колонке могут быть формулами — они не перезаписываются;
- колонки с датами дописываются правее ФИО.

Объединения ячеек, мешающие записи даты или отметки, снимаются автоматически.
Например, при объединении `B17:C17` ФИО остаётся в `B17`, а отметка пишется
в `C17`. Остальные объединения в строках студентов и примечаниях сохраняются.

## Порядок работы

### 1. Привязать карты

В списке есть ФИО, но нет кодов карт — карта отдаёт только число. Привязка
делается один раз:

```powershell
rfid enroll
```

Программа покажет **все группы предмета одним списком** со сквозной
нумерацией. Студент прикладывает карту, вы вводите **только номер** —
ни ФИО, ни группу набирать не нужно, группа берётся из файла.
Уже привязанная карта не переспрашивает, а показывает, за кем закреплена.

```
  1000000/10001
      1. Тестов Тест Тестович
      5. Примеров Пример Примерович
     25. Образцов Образец Тестович

  1000000/10002
     26. Студент Двадцать Шесть
     42. Студент Сорок Два

  Карта прочитана: A10007002A
  Номер студента из списка: 5
  Привязано: Примеров Пример Примерович (1000000/10001)
```

Можно и без отдельного захода: `rfid scan --enroll` (в меню «Отмечать
и сразу привязывать новые карты») — пара идёт как обычно, а на незнакомой
карте программа показывает студентов без карт и спрашивает номер.

### 2. Отмечать

```powershell
rfid scan
```

Спросит предмет, дальше студенты прикладывают карты. При выходе время прихода
проставляется в файлы групп: у пришедших — `09:02`, у остальных — прочерк.
Ячейка со временем выделяется жёлтым, если студент отметился на 10 минут
или больше позже первого зарегистрированного студента на этом предмете
за день (среди всех его групп). Порог считается по точному времени, включая
секунды. При повторном экспорте подсветка пересчитывается.

### 3. Смотреть

```powershell
rfid report     # кто пришёл, кого нет, проценты по группам
rfid late       # опоздавшие — кто показывает конспект
rfid export     # перезаполнить все файлы групп из базы
rfid import     # взять в базу отметки, вписанные в файлы руками
rfid import --sync  # полная синхронизация, главнее таблицы
rfid whois      # приложить карту и узнать, чья она
```

## Команды

| Команда | Что делает |
|---|---|
| `rfid` | меню |
| `rfid enroll` | привязать карты: приложил карту — ввёл номер из списка |
| `rfid scan` | отмечать студентов; спросит предмет |
| `rfid scan --enroll` | отмечать и тут же привязывать незнакомые карты к студентам из списка |
| `rfid whois` | чья карта; ничего не записывает |
| `rfid subjects` | предметы и группы, найденные в `tables/` |
| `rfid students list\|remove` | какие карты к кому привязаны |
| `rfid unknown` | карты, которые прикладывали, но не привязали |
| `rfid report [--date ДД.ММ.ГГГГ] [--group ...]` | кто пришёл, кого нет |
| `rfid late [--date ДД.ММ.ГГГГ] [--subject ...]` | опоздавшие на 10 мин и больше — показывают конспект |
| `rfid export` | проставить отметки во всех файлах групп |
| `rfid import [--subject ...]` | взять из файлов групп отметки, которых нет в базе |
| `rfid import --sync [--yes]` | полная синхронизация: главнее таблицы, затем файлы переписываются |
| `rfid reset marks\|cards\|all` | очистить базу; файлы групп не трогает |
| `rfid doctor` | считыватель, зависимости, состояние папок и базы |
| `rfid ports` | список COM-портов |

Общие флаги: `--db` (файл базы, умолч. `data/attendance.db`) и `--tables`
(корень с папками предметов, умолч. `tables`).

Режим `keyboard` — это **не** эмуляция клавиатуры считывателем (этот чип так
не умеет), а запасной ручной ввод кода. Включается только явным
`--mode keyboard`: если считывателя нет, программа так и скажет, а не начнёт
молча просить цифры.

## Где что лежит

| Путь | Что это |
|---|---|
| `tables/` | корень; внутри — папки предметов |
| `tables/<Предмет>/*.xlsx` | ваши списки групп; программа их заполняет |
| `data/attendance.db` | отметки и привязки карт |
| `driver/` | драйвер, если распакован рядом; в репозиторий не попадает |
| `example/` | чужой код, прислан для справки, не используется |

Отметки живут в базе, файлы — их отражение. Файл можно испортить или удалить
строку с датой: следующий `rfid export` восстановит всё из базы.

**При расхождении главнее база.** Отметки, вписанные в Excel руками,
которых в базе нет, забирает `rfid import`; каждая запись в файл
(`export` и выход из `scan`) делает это сама, поэтому дописанный руками
студент не затирается прочерком, а непонятное значение вроде «+»
остаётся в ячейке. А вот исправленное в Excel время вернётся к тому,
что в базе.

Чтобы главной стала таблица — `rfid import --sync`, в меню «Обновить
базу из файлов групп» → «Полная синхронизация». Время берётся из таблиц,
отметки, против которых в таблице прочерк или пусто, удаляются, затем
файлы переписываются из базы. Перед удалением программа показывает
список и спрашивает подтверждение. Отметки, сделанные позже, чем файл
последний раз сохраняли, не удаляются: прочерк там поставил прошлый
экспорт, а не человек.

Людей из списков импорт заводит в базе без карт — карту можно привязать
позже, втянутые отметки при этом останутся за человеком.

Если файл открыт в Excel в момент записи, программа скажет об этом и ничего
не потеряет.

## Что считается дублем

Повтор на **одном и том же предмете** в один день. За день студент может
отметиться на нескольких парах — это разные предметы, разные отметки.
Гарантируется ограничением `UNIQUE(day, subject_id, card_code)` в базе,
поэтому «уже отмечен» работает и после перезапуска программы.

## Слабое место: связь по ФИО

Кодов карт в ваших списках нет, поэтому привязка хранится в базе и опирается
на **совпадение ФИО**. Регистр, «ё» и лишние пробелы значения не имеют, но если
поправить фамилию в файле, связь с картой порвётся. Программа об этом скажет
при заполнении:

```
   не найден в списке: Тестов Тест Тестович
```

Лечится повторным `rfid enroll` для этой карты.

## Считыватель

`USB\VID_0403&PID_1234` — FTDI, то есть виртуальный COM-порт, 9600 бод, 8 бит,
без чётности, **2 стоп-бита**.

```
Em-Marine[A100] 007,42\r\n      карта поднесена
No card\r\n                        карта убрана
```

Код карты — 40 бит: `[HHHH]` старшие 2 байта, `FFF` серия, `NNNNN` номер.
Хранится как 10 шестнадцатеричных цифр: `A10007002A`.

**Префикс в скобках обязателен.** Он различается между картами, и без него две
разные карты могут совпасть по `FFF,NNNNN` и слиться в одного студента.

## Нужен ли драйвер

Зависит от PID устройства:

| PID | Драйвер |
|---|---|
| `1234` — IronLogic | **ставится вручную и форсированно.** Windows про этот PID
  не знает, в каталоге Microsoft Update по IronLogic пусто |
| `6001` — стандартный FTDI | **Windows ставит сама.** Воткнул — работает |

Чтобы получить plug-and-play на любом компьютере, PID меняют с `1234`
на `6001` утилитой **FT-Prog**; у IronLogic есть официальная инструкция
«Восстановление исходного (FTDI) PID». Программа ищет считыватель
по обоим PID, так что после перепрошивки менять в ней ничего не нужно.

Две оговорки. Перепрошивать надо на машине, где драйвер уже работает:
FT-Prog общается с чипом через него. И фирменные программы IronLogic
после смены PID могут перестать видеть устройство — ради этого они свой
PID и завели; нам их софт не нужен, а обратный переход тоже описан.

Про ручную установку (она двухэтапная и неочевидная) — см.
[instruction.md](instruction.md).

## Разработка

```powershell
venv\bin\python.exe -m pip install -e ".[dev]"   # редактируемая установка из src\
venv\bin\python.exe -m pytest -q
venv\bin\python.exe -m pyright                 # проверка типов, должно быть 0 errors
uvx ruff check                                  # линтер, настройки в pyproject.toml

rfid --db data/demo.db scan --mode mock   # прогон без железа

# --mode mock намеренно не работает с рабочей базой: он проигрывает
# вымышленные карты и испортил бы настоящие привязки.
```

Тесты парсера построены на синтетических строках в формате считывателя.
`tests/data/reader_lines.txt` содержит минимальный набор из двух строк карт
и событий `No card`, также используемых в тестах. Тесты разбора списков
создают временные таблицы с вымышленными студентами, объединёнными ячейками,
номерами-формулами и примечанием под списком; личные файлы не требуются.
