# Задание для сессии на компьютере: собрать и выпустить v1.3.0

Эту сессию запустили на Windows-компьютере пользователя, потому что собрать
exe можно только на Windows. Прошлая сессия работала в облаке (Linux), и там
сборка невозможна, а GitHub Actions сейчас не запускаются: аккаунт `s1nRo`
заблокирован из-за проблемы с оплатой.

Сначала прочитай `CLAUDE.md`. Особенно разделы «Портабельная сборка» и
«Замена карты у студента» в «Решениях, которые стоит сохранить».

## Что уже сделано и лежит в `main`

- **Портабельная сборка для флешки.** Папка `RFID-Portable` содержит
  `RFID-Scanner.exe`, `portable.txt`, `tables\`, `driver\CDM_2.12.36.20\`
  и `README.txt`. Если рядом с exe лежит `portable.txt`, база и списки
  хранятся на флешке.
- **Установка драйвера из окна.** Если считыватель воткнут, а драйвера нет,
  кнопка «Начать сканирование» предлагает поставить драйвер с флешки.
  Программа перезапускает exe через UAC с `--install-driver` и делает оба
  этапа через SetupAPI (`src/rfid/scanner/driver.py`, `_setupapi.py`).
- **Замена карты у студента.** Вкладка «Студенты и карты» → «Заменить
  карту…» / «Снять карту».
- В облаке проходят 433 теста, ruff и pyright без замечаний.
  **На Windows и на живом железе ничего из этого ещё не запускалось.**

## Что сделать

### 1. Подготовка

```bash
git checkout main
```
```bash
git pull origin main
```

Проверь, что есть пакет драйвера: в `driver\CDM_2.12.36.20\` должны лежать
`ftdibus.inf` и `ftdiport.inf`. Папка `driver\` в `.gitignore`, в git её нет.
Если папки нет, скачай ассет `ironlogic-driver-2.12.36.20.zip` из релиза
v1.2.0 и распакуй его в `driver\`:

```bash
gh release download v1.2.0 -R s1nRo/scanner-RFID -p "ironlogic-driver-*.zip" -D driver
```

Нужен обычный Windows Python 3.11 или новее (`py -3`). MSYS-venv из `venv\`
для сборки не годится: под него нет колёс PyInstaller (см. CLAUDE.md,
«Окружение»).

### 2. Тесты на Windows

`build-exe.cmd` сам создаёт `build-venv\`. Для тестов нужен venv с
`.[gui,dev]`:

```bash
build-venv\Scripts\python.exe -m pip install -e ".[gui,dev]"
```
```bash
build-venv\Scripts\python.exe -m pytest -q
```

Если `build-venv\` ещё нет, сначала запусти шаг 3 и вернись сюда.
Все тесты должны пройти, включая тесты окна (`test_gui_*`). Если что-то
падает только на Windows, почини, закоммить и запушь в `main`, и только
потом собирай.

Отдельно проверь вызовы SetupAPI через ctypes: в облаке их нельзя было
запустить, раскладки структур не проверены.

```bash
build-venv\Scripts\python.exe -c "from pathlib import Path; from rfid.scanner import driver as d; print(d.check_package(Path('driver/CDM_2.12.36.20')) or 'models ok'); print(d.WindowsBackend().reader_nodes())"
```

Должно напечатать `models ok` и список узлов считывателя (пустой, если
считыватель не воткнут). Ошибка здесь — ошибка в `_setupapi.py`, её нужно
починить до релиза.

### 3. Сборка

```bash
build-exe.cmd
```
```bash
build-portable.cmd
```

Результат лежит в `dist\RFID-Portable\`. Проверь, что там есть
`RFID-Scanner.exe`, `portable.txt`, `README.txt`, `tables\` и
`driver\CDM_2.12.36.20\ftdibus.inf`. Папки `data\` там быть не должно.

### 4. Проверка exe

1. Скопируй `dist\RFID-Portable` во временную папку (лучше на флешку)
   и запусти `RFID-Scanner.exe` оттуда.
2. Окно должно открыться **без вопроса о папке**, а рядом с exe должен
   появиться `data\attendance.db`.
3. В реестре не должно появиться ничего нового:
   `HKCU\Software\RFID Attendance\RFID Journal\workspace`.
4. Положи в `tables\` папку предмета со списком группы и убедись, что
   предмет виден в окне.

### 5. Проверка с живым считывателем (с пользователем)

Это главная непроверенная часть, в CLAUDE.md она помечена как
**ГИПОТЕЗА**. Делать только вместе с пользователем: это его компьютер
и его драйвер.

- **Драйвер уже стоит** (на машине разработчика это `COM3`): «Начать
  сканирование» должно работать как раньше. Приложи карту, отметка
  должна появиться.
- **Установка драйвера с флешки** — желательно на другом компьютере,
  где драйвера нет. Воткнуть считыватель, нажать «Начать сканирование»,
  согласиться на предложение поставить драйвер, подтвердить UAC. Должны
  пройти оба этапа, появиться COM-порт, а сканирование запуститься само.
  - Если не получилось, возьми текст из окна ошибки и конец
    `C:\Windows\INF\setupapi.dev.log` (последняя запись про
    `VID_0403&PID_1234`) и чини по ним.
  - **Не сноси работающий драйвер** на основной машине ради проверки:
    там он ставился вручную, и это рабочее место пользователя.
- **Замена карты:** «Студенты и карты» → выбрать студента → «Заменить
  карту…» → «Приложить новую карту к считывателю». Сканирование при этом
  должно быть остановлено.
  - **Не на живой базе.** Сначала сделай копию
    `data\attendance.db` (см. «Грабли» в CLAUDE.md: `data\` и `tables\` —
    рабочие данные пользователя).

По итогам обнови CLAUDE.md: что проверено, переведи с «ГИПОТЕЗА» на
«ПРОВЕРЕНО» с датой, и что пришлось чинить.

### 6. Релиз (только после подтверждения пользователя)

Упакуй папку в zip так, чтобы внутри была папка `RFID-Portable`:

```bash
powershell -NoProfile -Command "Compress-Archive -Path dist\RFID-Portable -DestinationPath dist\RFID-Scanner-1.3.0-portable.zip -Force"
```

Перед публикацией **спроси пользователя**: релиз публичный, его увидят все.
Покажи, какие файлы уйдут и какой будет текст.

```bash
gh release create v1.3.0 -R s1nRo/scanner-RFID --target main --title "v1.3.0 — версия для флешки" --notes-file RELEASE-NOTES.md dist\RFID-Scanner-1.3.0-portable.zip
```

`RELEASE-NOTES.md` напиши сам, по-русски, для пользователя, а не для
программиста:

- **Версия для флешки:** скопировал папку на флешку, база и списки едут
  вместе с ней.
- **Драйвер ставится из программы:** нужны права администратора один раз
  на каждом компьютере.
- **Замена карты у студента:** потерял карту или привязали не ту — прошлые
  отметки остаются за студентом.

**До сборки (шаг 3) подними версию:** в `src/rfid/__init__.py` сейчас
`__version__ = "1.2.0"` (`pyproject.toml` берёт номер оттуда). Поставь
`"1.3.0"`, закоммить и запушь в `main` отдельным коммитом. Только потом
собирай.
