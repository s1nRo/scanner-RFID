## Железо и драйвер — ПРОВЕРЕНО, РАБОТАЕТ

```
USB IronLogic RFID Adapter
USB\VID_0403&PID_1234\IL040PWZ      → USB Serial Port (COM3), SN=IL040PWZA
```

`VID_0403` — FTDI, считыватель работает как **виртуальный COM-порт**.

### Почему установка сначала не шла

У IronLogic два PID: **`6001`** (стандартный FTDI) и **`1234`** (свой). У устройства — `1234`.

| Архив | `PID_1234` в INF | Подпись | Итог |
|---|---|---|---|
| `cdm-v2.12.36.20-whql-certified.zip` | **нет** | SHA-256, актуальная | Windows: «драйвер не найден» |
| `drv_z2_z397_v2.12.26.zip` → `DRV_Win_All` | **есть** | WHQL, но SHA-1 от 2017 | Windows: «хеш отсутствует в каталоге» |

Второй вариант отвергается Code Integrity, в журнале `setupapi.dev.log`:

```
Error 0x80096002: The certificate for the signer of the message is invalid or not found.
Driver package INF file hash is not present in catalog file. Error = 0xE000024B
Driver package appears to be tampered, and Code Integrity is enforced.
Installing NULL driver!
```

На машине включён **Secure Boot**, поэтому отключить проверку подписи нельзя.

### Что реально сработало — принудительная установка

Взят **современный подписанный** пакет `driver/CDM_2.12.36.20/` и навязан устройству
через «Выбрать драйвер из списка» → «Установить с диска» → снять «Только совместимые
устройства». В журнале это видно как `Selected driver node does not match this device
(force-install)`. Secure Boot трогать не пришлось.

**Установка двухэтапная, это главная ловушка** — второй этап делается над ДРУГИМ узлом:

| Этап | Устройство | INF | Выбрать модель | Результат |
|---|---|---|---|---|
| 1 | `USB\VID_0403&PID_1234\IL040PWZ` | `CDM_2.12.36.20/ftdibus.inf` | `USB Serial Converter` | `ftdibus.sys`, появляется потомок |
| 2 | `FTDIBUS\COMPORT&VID_0403&PID_1234` | `CDM_2.12.36.20/ftdiport.inf` | `USB Serial Port` | `ftser2k.sys`, **появляется COM-порт** |

COM-порт создаёт только второй этап. Остановка после первого выглядит как
«драйвер не установился».

Замечание: на этой машине на этапе 1 по ошибке выбран `FT4222 Interface A` вместо
`USB Serial Converter`. Служба `FTDIBUS` при этом всё равно загрузилась и корректно
породила COM-порт-потомка, так что всё работает. Переделывать не нужно.

## Формат данных — ПРОВЕРЕНО на живом железе

**Параметры порта: 9600 бод, 8 бит, без чётности, 2 стоп-бита**, без управления потоком.
Подтверждено: приходит чистый ASCII без мусора.

```
Em-Marine[3C00] 078,17412\r\n      ← карта поднесена
No card\r\n                        ← карта убрана
```

Поведение, снятое с двух карт (`dump.txt`, `dump2.txt`):

- **в покое считыватель молчит** — ноль байт, никакого потока;
- **одно поднесение = ровно одна строка** с кодом, повторов при удержании нет;
- `No card` приходит **один раз**, через ~0.5–0.75 с, когда карту убрали;
- обе строки заканчиваются `\r\n`, строка с картой — ровно 27 байт.

### Разбор кода — префикс в скобках ЯВЛЯЕТСЯ частью ID

Проверено на двух разных картах: префикс различается между картами и стабилен
для каждой.

| Карта | Строка | 5 байт ID |
|---|---|---|
| A | `Em-Marine[3C00] 078,17412` | `3C 00 4E 44 04` |
| B | `Em-Marine[4D00] 135,29780` | `4D 00 87 74 54` |

Раскладка: `[HHHH]` — старшие 2 байта, `FFF,NNNNN` — младшие 3 байта, где
`FFF` = 1 байт серии, `NNNNN` = 2 байта номера. Вместе **40 бит** — в точности
размер идентификатора EM4100.

```
078,17412  →  78 * 65536 + 17412 = 5129220 = 0x4E4404
[3C00]     →  0x3C00
полный ID  →  0x3C004E4404  =  3C 00 4E 44 04
```

**Канонический код карты обязан включать префикс.** Если брать только `FFF,NNNNN`,
две карты с разными префиксами сольются в одного студента — тихая порча журнала.

### Что на карте лежит физически — ПРОВЕРЕНО (свойство стандарта)

Карта Em-Marine хранит **только неизменяемый номер**. Ни ФИО, ни группы, ни свободной
памяти. Связка «код → студент» создаётся нами вручную один раз и со считывателя
прийти не может.

Четыре подпакета по внешнему миру (рефакторинг 25.09.2026): `scanner` — железо,
`excel` — файлы пользователя, `db` — база, `cli` — человек. Связки между ними:
`journal` (db ↔ excel), `pipeline` (scanner → db → вывод).

- Всё консольное — внутри `cli`: вывод (`view`), клавиша выхода (`keys`),
  ввод. Считыватель получает только функцию `should_stop()`, цикл отметки —
  только интерфейс `pipeline.View`. Другой интерфейс заменит `cli` целиком.
- Зависимости идут в одну сторону. `scanner` не знает ни о чём снаружи.
  `excel` знает только `names` и `lessons`. `db` знает только `names`
  и `scanner.codes` (код карты). `db` и `excel` друг о друге не знают —
  их сводит `journal`. От `cli` не зависит никто.
- Снаружи пакета обращаются к его `__init__` (`excel.read_roster`,
  `scanner.make_reader`), а не к модулям внутри.
- Подмена в тестах — там, где имя ищется: поиск порта — `scanner.ports`,
  ввод — `cli.common.ask`. Поэтому `factory` зовёт `ports.find_reader_port()`
  через модуль, а CLI — `common.ask(...)`, а не импортом имени.

### Решения, которые стоит сохранить

- **Направление база → файл, при расхождении главнее БАЗА.** Пользователь
  25.09.2026 сначала выбрал «база главнее», потом «файл главнее», потом
  вернул «база главнее», а «таблицы главнее» вынес в отдельное явное
  действие — полную синхронизацию (см. «Схема 3» ниже). Отметки хранятся в SQLite, файлы групп
  их отражают. Открытый в Excel файл не мешает отмечать студентов: запись
  идёт при выходе и повторяется командой export.
- **Отметка принадлежит занятию, а не дню.** Схема 2: таблица `subjects`
  (`name` + `course`, оба задаются пользователем), у `attendance` есть
  `subject_id NOT NULL`. За день студент отмечается на каждой паре отдельно.
- **`UNIQUE(day, subject_id, card_code)`** — дедуп на уровне базы, переживает
  перезапуск программы среди дня. В памяти процесса его держать нельзя.
- **Таблицы даёт пользователь, программа их только заполняет.** Предмет —
  это имя папки в `tables/`, список предметов = список папок. Внутри папки
  по файлу на группу. Свои таблицы не генерируем: прежний `excel.py` удалён.
- **Формат списка разбирается гибко**: группа из строки «Группа …», шапка
  по слову «ФИО», конец списка по пустой ячейке. У настоящего файла
  объединены A1:Y1 и C2:Y2, номера в колонке A — формулы, а под списком
  примечание «Староста: …». Всё это ломает наивный разбор, поэтому номера
  берём по порядку строк, а перед записью дат снимаем объединение шапки.
- **Связь «карта → студент» держится на совпадении ФИО** (в списках кодов
  нет). Регистр, «ё» и пробелы не важны; правка фамилии связь рвёт, и об
  этом сообщается при заполнении — молча терять отметки нельзя.
- **Миграция схемы 1 → 2** переносит старые отметки в служебный предмет
  `(без предмета)`; она идемпотентна и покрыта тестами.
- **Отметка непривязанной карты сохраняется** с `student_id = NULL`, очередь
  не тормозится. Привязка позже делает прошлые отметки именными.
- **В отчётах видны отсутствующие**, а не только пришедшие.
- **Связь «карта → человек» создаётся только при живом контакте.** `rfid enroll`
  показывает список группы из файла, студент прикладывает карту, оператор
  вводит номер строки. ФИО не набирается — его неоткуда взять правильно,
  кроме как из присланного списка.

- **Режим `auto` не скатывается в ручной ввод.** Раньше при отсутствии порта
  он молча включал ввод кода с клавиатуры — человек ждёт, что приложит карту,
  а у него просят шестнадцатеричные цифры. Теперь отказ с объяснением,
  а `--mode keyboard` только по явному требованию.

- **`tables/` — корень, а НЕ предмет.** Предметы — её подпапки с `.xlsx`;
  сама `tables/` кандидатом быть не должна. Другой корень — через
  `--tables`. Файлы в корне мимо папок показываются как «не используются»
  в `subjects` и `doctor`, но не трогаются.
- **Раскладкой распоряжается пользователь, не программа.** Папок не
  создаём, файлов не переносим — только показываем найденное
  с предпросмотром (группа, сколько человек). Попытка автоматизировать
  (создать папку, перенести файлы) была отвергнута как лишняя опека,
  и вдобавок опасна: `read_roster` примет за список любой файл со словом
  «ФИО», включая старые сгенерированные таблицы.
- **Меню обязано протаскивать общие флаги** (`--db`, `--tables`, `--home`)
  в подкоманду: оно перезапускает main() и иначе теряет выбранные пути.

- **`--mode mock` запрещён с рабочей базой** (`guard_mock`). Показательный
  прогон проигрывает вымышленные карты, но писал туда же, куда настоящая
  работа: так в боевых данных оказались настоящие карты, привязанные
  к случайно выбранным людям. Для демонстраций — отдельная `--db`.

- **При привязке карт группу не спрашиваем.** Показывается сквозной список
  всех студентов предмета с подписями групп; группа подставляется из файла,
  где найден выбранный студент. Важен человек, а не файл.

- **`rfid reset`** чистит базу: `marks` (отметки и предметы), `cards`
  (привязки), `all`. Файлы групп не трогает никогда — они не наши.

- **Подтверждения — `(y/n)`, по просьбе пользователя.** Всё через
  `cli.common.confirm`: согласие только `y`/`yes`, остальное — отказ, включая
  «да» и «н» (это `y` в русской раскладке; начавший печатать «нет» не
  должен случайно подтвердить удаление). Новые вопросы — только через него.

- **`rfid late` (меню 5) — опоздавшие, «показывают конспект».** Считает
  через `lessons.late_arrivals`, то есть тем же `is_late`, что и жёлтая
  подсветка: список и таблица обязаны совпадать. Берёт только именные
  приходы (как и запись в файлы). День — выбором, Enter = последний.

- **`rfid scan --enroll` (меню 2) — отметка с привязкой на ходу**, просьба
  пользователя совместить enroll и scan. Это обычный `pipeline.run`, только
  вывод — `marking.BindingView`: на карте без владельца показывает студентов
  без карт и спрашивает номер. Отметка к этому моменту УЖЕ в базе
  (безымянная), `bind_card` забирает её себе — пропуск или опечатка
  ничего не теряют. Порт после вопроса **не сбрасывается** (в отличие
  от `rfid enroll`): карты, приложенные, пока оператор выбирал, — пришедшие
  студенты, сброс молча терял их отметки (баг 16.10.2026). Счётчик сеанса
  заводится снаружи `pipeline.run` (`tally=`), иначе Ctrl+C на вопросе
  давал «Отмечено: 0». Итог переносит
  привязанные из «неизвестных» в «отмечено»; «Прошлых отметок зачтено»
  не считает только что сделанную.

- **Меню — цикл, а не одноразовый запуск.** После действия возвращаемся
  к нему и ждём Enter. Выход: `0`, `q`, «выход», пустой ввод или Ctrl+C.
  Отказ от выбора — `Cancelled`, наследник `Interrupted` с пустым текстом:
  это не ошибка, сообщения быть не должно.

- **Plug-and-play достижим только сменой PID на 6001.** Для стандартного
  FTDI-PID Windows ставит драйвер сама (каталог Microsoft Update, 119
  записей, свежая 2.12.36.20 от 27.10.2024); для IronLogic-PID 1234 —
  ничего. Клавиатурный режим тут не выход: это другая модель, и ей тоже
  нужен драйвер (5.1.26). Поиск порта принимает оба PID, а при 6001
  различает наш считыватель по серийнику `IL…` — 6001 носит любой
  FTDI-переходник.

- **Опоздания считаются от начала ЗАНЯТИЯ, а не дня и не предмета.**
  Расписание со слов пользователя: **пара 1 час 40 минут, перемена 20**,
  то есть занятия идут ровно каждые два часа (`LESSON_CYCLE`).
  `marks` приходит общий на предмет, поэтому приходы сперва режутся
  на занятия, и уже внутри занятия опозданием считается `LATE_AFTER`
  (10 минут). Так покрыты оба случая: у групп с парами в разное время
  отсчёт свой, а на общей лекции опоздавшая группа видна.

  Три тонкости, каждая закреплена тестом:

  1. Отсчёт от НАЧАЛА занятия, а не от предыдущего прихода. Иначе
     пришедший под конец пары объявил бы себя новым занятием, а цепочка
     приходов по чуть-чуть растянула бы одно занятие на весь день.
  2. Порог — весь цикл, а не одна пара. Иначе карта, приложенная
     на перемене, создаёт фантомное занятие, и следующая пара целиком
     становится «опоздавшей». Приход на перемене лучше отнести
     к предыдущей паре.
  3. Сравнение нестрогое (`>=`): пары идут ровно через цикл, и приход
     точно через два часа — это уже следующая пара, а не опоздание.

- **Из цикла отметки выходят клавишей, а не Ctrl+C.** Цикл ждёт порт,
  поэтому опрос клавиатуры неблокирующий (`cli.keys.make_stop_watcher`,
  msvcrt.kbhit) и спрашивается в `SerialCardReader._expired()`.
  Причина не в красоте: Ctrl+C под Windows уходит всей группе процессов,
  и после выхода cmd.exe спрашивает «Завершить выполнение пакетного
  файла?» — внутри .cmd этот вопрос не подавить.
  Карты, уже прочитанные из порта до нажатия, дочитываются и пишутся:
  они физически приложены, терять их нельзя. Закреплено тестом.

- **Рабочая папка вместо текущей** (`src/rfid/cli/home.py`). База и
  `tables/` ищутся не от текущей папки: `--home`, затем `RFID_HOME` (его
  ставит `rfid.cmd` — своя папка), затем текущая, только если в ней уже
  есть `data/` или `tables/`. Иначе отказ, и ничего не создаётся. Причина:
  после установки пакета `rfid` запускается откуда угодно и тихо завёл бы
  пустую базу в чужой папке — отметки ушли бы мимо журнала. Относительные
  `--db`/`--tables` — от рабочей папки. `guard_mock` сравнивает resolved-пути.
- **Рабочая папка у окна и консоли одна** (16.10.2026, свели PR #4
  коллеги и мой #5 по решению пользователя «объединить»). Поиск — только
  `cli.home.find_home`: `--home`, `RFID_HOME`, рядом с собой (у exe — его
  папка, иначе текущая; только если есть `data/` или `tables/`), затем
  папка, выбранная в окне (`workdir.remembered`). Память в реестре
  `HKCU\Software\RFID Attendance\RFID Journal\workspace`, значение `home` —
  ровно там, где её писал QSettings в PR #4 (проверено пробным ключом),
  но через `winreg`: `rfid.exe` собран без PyQt5 и должен её видеть.
  Запомненная папка без `data/` и `tables/` не принимается.
  - Нет папки: консоль отказывает, окно (`cmd_gui`, `needs_home=False`)
    спрашивает её (`gui.ask_home`). Новую пустую — только с согласия.
  - Пустых `data/` и `tables/` в комплекте exe быть НЕ должно: в новом
    месте exe принял бы их за рабочую папку.
  - Обе точки входа (`packaging/`) идут через `rfid.cli.main`. У оконного
    exe консоли нет: `packaging/rfid_gui.py` перехватывает вывод и
    показывает отказ окном (признак — `sys.frozen`, а НЕ
    `sys.stdout is None`: в собранном exe второе не срабатывает).
  - `tests/conftest.py` глушит `workdir.remembered` во всех тестах: на
    машине разработчика там записана живая рабочая папка.
  - PyQt5 исключён из `rfid.exe` (10 МБ вместо 40).
- **src-раскладка и установка — потому что программу раздают** (решение
  пользователя 25.09.2026). Раздача — архив «Source code» релиза GitHub;
  `.gitattributes` выкидывает из него `tests/` и служебное. Получатель
  запускает `install.cmd` один раз. Проверено сборкой `git archive`
  и установкой на чистом Python 3.11.

- **Схема 3: человек отдельно от карты.** `students.card_code` может быть
  NULL, личность — `(name_key, group_name)`, где `name_key` —
  `normalize_name(ФИО)`. Нужно для `rfid import`: в списках 89 человек,
  карт привязано 2, втягивать отметки иначе было бы не для кого.
  Следствия, каждое закреплено тестом (`tests/test_import.py`):
  - `import` обычный — **база главнее**: добавляет недостающее, другое
    время в файле → `ImportStatus.KEPT`, база не меняется. Сравнение до минуты,
    чтобы секунды живых приходов не давали ложных расхождений. Поиск
    существующей отметки — по `student_id` или карте, т.к. NULL-карту
    UNIQUE не ловит. Заводит ВЕСЬ список группы. Файл — одной
    транзакцией (SAVEPOINT, вкладывается). `raw = "таблица: <файл>"`.
  - `import --sync` / меню 10 → 2 — **полная синхронизация, главнее
    таблицы** (`journal.sync_subject`): время из файла правит базу,
    прочерк/пусто УДАЛЯЕТ отметку, затем `fill_subject`. Сперва пробный
    прогон (`dry_run` — всё в одной точке сохранения и откат), список
    удаляемого, подтверждение `(y/n)`. Не удаляются: отметки новее mtime
    файла (прочерк поставил прошлый экспорт, не человек), непонятные
    ячейки, дни без колонки в файле.
  - `fill_subject` **сначала импортирует недостающее** (обычный режим),
    потом пишет. Файл, импорт которого не удался, не перезаписывается.
  - `excel.attendance.write_attendance` ставит «—» только в ячейку, где пусто или уже
    прочерк. Время и непонятное («+») не затираются никогда.
  - При привязке карты к человеку без карты `_stamp_card_on_marks`
    проставляет карту в его безкарточных отметках; при конфликте с живым
    приходом за то же занятие остаётся приход.
  - Вторая карта тому же человеку — `CardConflict`, а не молчаливое
    «Привязано».
  - `students remove` и `reset cards` **отвязывают, а не удаляют**
    человека: иначе отметки из таблиц стали бы ничьими и невидимыми.
    Отметки картой возвращаются в «неизвестные».
  - Год даты «дд.мм» — текущий, если дата не в будущем, иначе прошлый.
  - Непонятные ячейки (`+` и т.п.) не угадываются, а выводятся списком.

### Потеря отметки — главный враг

Студент приложил карту и ушёл. Если отметка не записалась, узнать
об этом неоткуда: карта у него, очередь идёт дальше. Аудит 25.09.2026
нашёл четыре пути потери, все закрыты и покрыты `tests/test_loss.py`:

1. **Сбой вывода убивал сеанс.** Исключение из `view.show` выносило
   цикл, и все следующие студенты молча не отмечались. Теперь запись
   и показ обрабатываются по отдельности: отметка уже в базе, показ —
   дело десятое.
2. **Одна неудачная запись убивала остальные.** Теперь считается
   в `pipeline.FAILED`, кричит в консоль с кодом карты и временем,
   и попадает в итог сеанса. Молча терять нельзя.
3. **Занятая база не давала даже открыться.** `_repair_orphan_marks`
   и запись `schema_version` брали блокировку при каждом открытии,
   а `busy_timeout` не был выставлен — второе окно программы роняло
   запуск. Теперь обе операции сперва проверяют, есть ли что писать,
   плюс `PRAGMA busy_timeout`.
4. **Один битый файл блокировал выгрузку всех групп.** `_fill_one`
   ловил только RosterError и PermissionError; пустой .xlsx рядом
   ронял `fill_subject` целиком. Теперь ошибки ловятся пофайлово
   и широко.

Известные ограничения, оставленные осознанно:

- Карта, перевыпущенная другому человеку, заберёт себе прошлые
  безымянные отметки прежнего владельца. Различить это от исправления
  ошибочной привязки автоматически нельзя, а исправление — более частый
  случай. Число зачтённых отметок показывается при привязке, так что
  странность видна.
- Два студента с одинаковым ФИО в одной группе получат одну и ту же
  клетку. В настоящих списках пользователя повторов нет.

### Грабли, на которые уже наступали

- **Первый exe (PR #3, `windows_launcher.py`) открывал `data/rfid.db`**
  вместо `data/attendance.db` и сам создавал `data/` и `tables/` где угодно.
  В папке программы он поднялся бы с пустой базой: прошлые отметки
  и привязки «пропали» бы, а новые ушли в другой файл. Исправлено
  16.10.2026 до раздачи: имя базы задаёт только `cli.home.DB_FILE`.
- **Запись в список группы ОБЯЗАНА быть атомарной.** `openpyxl.save(path)`
  сначала обнуляет файл и только потом пишет: сорвавшаяся запись оставляет
  0 байт. Поймано 25.09.2026 при проверке блокировки — список из деканата
  был уничтожен полностью. Восстановить неоткуда: в базе лежат отметки,
  а не состав групп. Теперь `excel.save.save_atomically` пишет во временный файл
  рядом и подменяет через `os.replace`. Закреплено тестами на оба сбоя:
  падение самой записи и падение подмены.
- **Excel действительно блокирует запись** (проверено через COM на живом
  Excel, не по памяти): пока книга открыта, `os.replace` даёт
  PermissionError. Отметки при этом в базе, теряется только запись
  в файл — лечится `rfid export` после закрытия.

- **Создание студента ОБЯЗАНО забирать прошлые безымянные отметки его карты.**
  Реальный баг 20.09.2026: карту прикладывали до того, как владельца завели
  в справочник, `add_student` привязку не делала — и отметка навсегда
  оставалась ничьей. Снаружи это выглядело так: карта висит в «неизвестных»,
  студент числится отсутствующим, а повторное прикладывание отвечает
  «уже отмечен», потому что `UNIQUE(day, subject_id, card_code)` уже занят.
  Тихая порча данных. Привязка теперь внутри `add_student`, а при каждом
  открытии базы ещё и работает `db.schema._repair_orphan_marks()` — страховка,
  чинящая записи, испорченные прежними версиями.
- **Название группы бывает без слова «Группа».** В реальном файле
  встретилось `ИКНК 5132704/30701` в B1. Поэтому `_detect_group` пробует
  три способа: «Группа X», затем номер по виду (`\d{3,}[/.-]\d{2,}`),
  затем первую непустую строку над шапкой. Имя файла — последнее средство.
- **Имена групп со слэшем** (`5132704/30801` — реальный формат у пользователя)
  нельзя использовать как имя листа или файла. Сейчас это и не нужно:
  файлы даёт пользователь, мы их только заполняем.
- **`data/` и `tables/` — рабочие данные пользователя, а не мусор.**
  Не удалять их в ходе проверок: там живая база и открытые в Excel таблицы.
  Для прогонов заводить отдельную базу через `--db`.

- **`sys.stdin` надо переводить в UTF-8 наравне с выводом.** В Windows поток
  открывается в cp1251 с `surrogateescape`, кириллица из пайпа превращается
  в суррогаты, и SQLite падает с `UnicodeEncodeError: surrogates not allowed`.
  Лечится `reconfigure` в `cli.common.setup_console()`.
- **Не генерировать Python через bash-heredoc с обратными слэшами.**
  Дважды подряд `\\n` внутри heredoc превратился в настоящий перенос
  и порвал f-строки. Если правка требует escape-последовательностей —
  писать файл целиком или собирать слэш как `chr(92)`.
- **`rfid.cmd` только ASCII.** `cmd.exe` читает `.cmd` в OEM-кодировке, и
  кириллица даже в комментарии `REM` разваливается на несуществующую команду.

### `example/` — чужой код, принимать с оговорками

Прислан пользователем как образец, написан не нами.

- `scanner_reader.py` — под **сканер-клавиатуру** (штрихкод), а не под COM-порт.
